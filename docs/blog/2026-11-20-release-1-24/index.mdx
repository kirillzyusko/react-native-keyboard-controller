Version `1.24.0` is an intentionally small release ahead of React Native 0.89. It adds Swift Package Manager (SwiftPM) support on iOS and on-demand view managers on Android.

## 📦 Swift Package Manager on iOS

The npm package now includes a `Package.swift` manifest so React Native can autolink the library in apps that use SwiftPM. CocoaPods remains supported, and `1.24.0` continues to work with earlier supported versions of React Native.

You can already use `1.24.0` with the opt-in SwiftPM setup in React Native 0.88. If your app uses SwiftPM, update the package and rebuild your iOS app.

## 🤖 On-demand view managers on Android

If a native view only appears on a later screen, its configuration can wait until you get there. `KeyboardControllerPackage` now implements `ViewManagerOnDemandReactPackage` so React Native can do that setup on demand for the library's views.

:::note What we measured

Median JS-thread CPU time in `UIManager.getConstants` went from 29.9 ms to 27.0 ms, a saving of **about 3 ms**. Each release build was measured over 10 cold starts in `FabricExample` with React Native's lazy getter fix applied.

:::

I'll happily take a few milliseconds from one package. Now imagine 30 packages each deferring the same amount of JS-thread work. That would add up to roughly 90 ms of CPU work moved out of startup.

## 🤔 What's next?

I'm also working on the interactive back swipe on iOS. When you're writing a reply, you might swipe back far enough to peek at the conversation list and then decide to keep typing. The composer should stay in sync with the keyboard the whole time so you can pick up right where you left off.
