`1.23.0` is intentionally a small release. There is no big new component this
time — instead it makes `KeyboardAwareScrollView` track the focused input more
precisely, removes the remaining visual artifacts of the keyboard preload, and lets
`KeyboardExtender` drop its background.

<!-- truncate -->

## 🎯 More precise focused input tracking

`KeyboardAwareScrollView` scrolls to the caret of the focused input, so its
accuracy depends entirely on how precisely the native side reports where that
caret is. This release reworks how iOS collects this information: iOS now
reports geometry similar to Android, and `KeyboardAwareScrollView` becomes
more consistent across platforms.

:::warning `bottomOffset` and `paddingTop`
Previously, on iOS the caret position of a single-line `TextInput` ignored its
`paddingTop`, so the caret was reported higher than it really was. Because of
that `KeyboardAwareScrollView` stopped scrolling a bit too early and the text
could end up under the keyboard. If you compensated for that with a bigger
`bottomOffset`, you may now be able to reduce it on iOS.
:::

## 🧹 `preload` with fewer artifacts

`KeyboardProvider` preloads the keyboard on iOS by default to remove the lag of
the very first focus. Some developers reported that the preload itself could be
visible: the keyboard flashed over the first screen when the app was launched
from Spotlight with the Spotlight keyboard still open. This is fixed in
`1.23.0`.

If you disabled `preload` or called `KeyboardController.preload()` manually at
a "safe" moment to work around these artifacts, give the default behavior
another try:

```diff
-<KeyboardProvider preload={false}>
+<KeyboardProvider>
```

If you still see the keyboard flashing or any other side effect — please
[open an issue](https://github.com/kirillzyusko/react-native-keyboard-controller/issues/new?template=bug_report.md)
with the steps to reproduce it. I'd like to fix the remaining cases.

## ⬜ `transparent` prop for `KeyboardExtender`

`KeyboardExtender` always wrapped its content in a keyboard-styled container: a
full-width glass capsule on iOS 26+, and a keyboard background on earlier iOS
versions and Android. That's a good default for a bar with several controls,
but not for a lone control that should sit on the keyboard on its own — a
floating "Done" pill like the native `UIToolbar` draws for a single trailing
item, or a row of buttons similar to the ones WhatsApp attaches to the keyboard
in its image editor:

<Video src="/video/keyboard-extender-whatsapp.mp4" width={35} />

The new `transparent` prop removes that container, so your content draws its
own surface:

```tsx
import { KeyboardExtender } from "react-native-keyboard-controller";

function DoneExtender() {
  return (
    <KeyboardExtender transparent>
      <DonePill />
    </KeyboardExtender>
  );
}
```

- **iOS 26+**: the glass capsule is skipped, the content keeps the same offset
  above the keyboard.
- **iOS < 26**: no keyboard background is drawn behind the content.
- **Android**: the keyboard background view is skipped.

The prop defaults to `false`, so nothing changes for existing usages, and it
can be toggled at runtime — even while the keyboard is open. Thanks to
[kylesuss](https://github.com/kylesuss) for proposing and implementing it
([#1714](https://github.com/kirillzyusko/react-native-keyboard-controller/pull/1714)).
You can read more on the
[`KeyboardExtender` API page](/docs/next/api/views/keyboard-extender).
